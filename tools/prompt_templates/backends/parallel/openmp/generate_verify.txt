@@ review_target_scope
On this backend the model's own loops may run on several threads; the host runs the binary at several thread counts and compares each run with a one-thread run. What makes a returned value wrong here is a data race: a variable written by more than one thread of a region without the reduction, private copy or ordering the result needs, or one thread's write read by another with no synchronization between them. One construct is a finding here although it makes no value wrong: a region pinned to one thread or switched off on every case the tests run — `num_threads(1)`, `omp_set_num_threads(1)`, an `if(...)` clause false on all of those cases — runs at one thread in every run, so the comparison cannot see a race in it. Two constructs are not this finding: a `num_threads(k)` with `k > 1`, because each run's thread limit caps it at that run's width; and an `if(...)` clause true on at least one case the tests run, because the region runs at each run's width on that case and every run is compared on every case.
