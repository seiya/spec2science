## Format notes (read before fanning out to ~56k lines)

1. **A `kind` tag is needed.** "Check" covered six different things in these files, and a classifier treats them differently. I put the tag at the start of column 3 rather than adding a column; a real column is better. The tags:
   - `[refusal]`: raise, or a refused result
   - `[skip-ok]`: returns `ok: True, skipped: True`, so a later reader decides
   - `[guard]`: a silent normalisation, drop, or rewrite, with no message
   - `[record]`: a file or field written for a later reader
   - `[import-check]`: fails the module import
   - `[catch-all]`: an exception is turned into a verdict; the polarity is stated
   - `[pointer]`: the check lives in another module that this file only calls
2. **Pointer rows keep the fan-out from double-counting.** When a file only calls a check owned by another module (`workshop_tree`, `runner_ir`, `primary_evidence`, `orchestration_runtime.render_wrapper_sandbox_prefix`, `registry`), I wrote one `[pointer]` row naming the owner. The full row belongs to the owner's inventory. Rule proposal: **a check is inventoried in the module that raises or decides it.** A shared constant (`CASE_ID_TOKEN_RE`) is inventoried once, at its definition, with every consumer listed.
3. **The four author classes do not fit everything.**
   - The DEV hook layer's input is the command an interactive agent session types. I used `dev-session`.
   - Many arguments are type checks on values that no in-tree caller passes at all (`sources`, `target`, `jobs`, `command` on the preset tools, an absent `build_system`). I wrote `host (no in-tree caller passes it)` and named the grep. Suggestion: add an explicit `none (no caller)` author value.
   - `problem_procedure_names` is reached with an operator-chosen member on the spec-input path and a **leaf-chosen** member (IR `dependency.direct_deps`) on the Compile-gate path. Per-path authorship (`mixed`, paths listed) was necessary. Only listing every caller showed this.
4. **Pin strength must be tagged; a bare "test name" is misleading.** Exact-string grep of the messages gave many false "none found": tests assert a fragment, a regex, or the exception type only. Symbol grep also gave false hits (`test_case_set`, `model_alone` and `max_wrapper_calls` hit unrelated tests). I built column 5 from the assertion sites and tagged each pin:
   - `(msg)`: asserts the message text or a fragment of it
   - `(type)`: asserts the exception type or result category only
   - `(sym)`: mentions the symbol, but does not drive this branch
   - `(cat-masked)`: asserts only a category that a LATER check also returns for the same input. Removing this check would leave the test green. Two examples: `test_run_resolves_every_path_itself`, and the syntax `test_rejects_custom_command`, which passes no `compiler`/`std`, so the required-argument refusal raises the same `ValueError` if the custom-command check is removed.

   Suggestion: a fan-out agent should open each candidate test and tag it, not grep a message.
5. **Granularity.**
   - Type checks repeated verbatim across the five `tool_*` entry points (`command_log_path`, `env`, `_bounded_int`, sandbox keys) are ONE row with N locations.
   - Type checks specific to one entry point are one row per function.
   - Distinct refusals in one function (for example the `run` op's 9 refusals) are one row each, because each has its own message and its own author trace.
   - A family of schema checks in one reader that share a message pattern (`lint evidence X must be …`) is one row.

   Suggestion: state this rule in the fan-out brief.
6. **The "callers of operator/host values" column is the expensive one, and the valuable one.** The pilot found three cases where a check that reads like operator policing also bounds a leaf value on another path:
   - `CASE_ID_TOKEN_RE`
   - `problem_procedure_names`
   - `_lint_source_files`' `./` prefix

   Recommendation: keep the column. Require the agent to list the grep it ran, so a reviewer can re-run it.
7. **Missing column: "downstream / duplicate of".** A classifier needs to see the check that runs again on the same value: the launch gate vs `build_runtime`'s build-system checks, the host gate vs the wrapper's feedback copy, the spec-input gate vs its backstops. I put this in notes. A dedicated column would make the merge candidates scannable.
8. **Standing-decision tags are judgment calls at the margin.**
   - The `build_runtime` rows for build systems no backend owns (cargo/go/maven/gradle/npm/pnpm/poetry) are arguably the #173 surface. I tagged them `standing?: #173`.
   - The `dev_cli` codex encoding is a DEV-layer CLI, not a leaf provider, so #172 may not apply. I tagged it `standing?: #172 (DEV layer)`.

   The classifier should confirm both.
9. **Mechanics.** The DEV hook (HK-02/HK-04) refuses any Bash command whose TEXT contains the hard-reset string or a sleep with a duration. Fan-out agents that grep for those messages must spell them as regexes (`reset --h[a]rd`). This pilot was refused once.
