**Facts I checked against the code at ec2ddda3, beyond what the inventory says:**
- The only `build_system` backend is `make` (`ls tools/backends/build_system/`). The launch gate `target_profile.toolchain_servable_reasons` (:642, called at :843) refuses an unimplemented `build_system`. So no profile reaching the library names cmake, meson, ninja, cargo or the other unowned names.
- Every `WrapperContext` with `compile` is built at workflow_conductor.py:11303 with `build_system=tc["build_system"]`. The IR-check context at :11371 serves no `compile`. No in-tree caller omits `build_system`.
- The wrapper's module docstring (L20-21) says: "Results are FEEDBACK. The host's own gates run on the snapshot and are the authority; nothing a gate reads is written here." The snapshot (`workshop_tree.snapshot_tree`, :844) copies the tree, and the hand-off reassembles the bundle from the manifest. Nothing a wrapper `run` produces reaches a gate that the leaf could not already write itself.
- The wrapper's category names (`wrapper_error`, `build_graph_failed`, `syntax_error`, `run_unavailable`, …) have no reader except the leaf. `rg` over `tools/` (excluding tests), `tools/prompt_templates/` and `tools/leaf_contract.py` finds none. The conductor's `syntax_error` is its own constant.
- The CLI transport refuses an off-lineage tool name itself (workshop_mcp.py:360). On HTTP, `call_tool` (workflow_conductor.py:8270-8277) goes straight to `run_wrapper_op`. So WW-01 is the only op-set check on HTTP.
- The `-x` / `../x` worry for `binary`: the run argv is `str(ctx.paths.staged_bin / binary)` (workshop_wrapper.py:703), an absolute path, so no option-shaped word reaches the argv. An ABSOLUTE `binary` (`/bin/sh`) replaces the join, so without WW-26 the run would start that system program inside the sandbox.
- The generate.generate seeds always carry `spec.ir.yaml`. Both generate contexts carry `ir_document` (workflow_conductor.py:6444, :6536), and it maps to `spec.ir.yaml` in the seed tables (:7844, :9517-9533).
- The registry refuses a capability declared in both core_provides and backend_provides (registry.py:717-721). It also requires each composite's record to carry `lint` in core_provides and each member to carry it in backend_provides (:742-761). BR-18's two arms therefore cannot fire.
- The lint certification re-checks the evidence itself (validate_pipeline_semantics.py:4955-4995: `ok is True`, preset, `run_linter` a non-empty array, entries are objects). `_verify_command_log_record` says "callers validate command_id / log_ref presence before calling". A lint run that BR-21 skipped is recorded by the conductor with `command_id ""` (:12196-12201). The certification refuses that evidence, so a leaf cannot make lint vacuous through the skip.
- **The discriminator applied to the wrapper's rows.** A wrapper row is `keep:break` (feedback fidelity) when, without it, a CORRECT call — one naming the leaf's own tree, its built binary, its declared cases — would get an answer that disagrees with the host gate. That covers a stale object answering for the tree (WW-35), a leaf-edited seed (WW-06), a model-alone failure (WW-18), and a skip shaped as pass or fail (WW-19). A row is a `remove` candidate when it changes only the answer to a MALFORMED call. Such a row matters to no correct leaf, and gains no leaf anything at the host: the results are feedback, and the host gates rerun on the snapshot (module docstring L20-21). Rule 1-e covers the "gain is nothing" half. The "it still ends red" half is a fallback I read but did not run, so every such row carries **needs-run**, judged with the WHOLE group removed together.
- With `case_ids` given, `cases_file` is never used after `_tree_file` (L652-655). The command passes `seeded_path` (L694, L703).
- `test_derivation_transformation_drift.py` digests `build_runtime.tool_compile_project`, `_run_command`, `build_command`, `default_build_jobs`, `COMPILED_LANGUAGE_BUILD_SYSTEMS`, `tool_run_program`, `tool_run_quality_checks`, `quality_check_command` and `_QUALITY_CHECK_PRESET_COMMANDS` (:333-490). It digests nothing in workshop_wrapper, spec_input_gates, hooks or audit_orchestration. A row marked **[drift]** touches a digested source and needs a re-pin decision.
