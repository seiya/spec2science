## Shared facts (cited by the rows as S1..S7)

- **S1: who authors the IR.** The `spec.ir.yaml` is authored by the leaf (the `compile.generate` workshop leaf) and serialized by the host. Every compile-stage gate in this range reads leaf content.
- **S2: which `tests.md` gates (m)/(o)/(r)/(q) and VP2-76 read.**
  - The path comes from the IR's `meta.source_refs.tests`, which the leaf writes; it is resolved by `_tests_path_from_ir_document` (vps:3727).
  - The conductor's document check pins that field to the node's own spec `tests.md` when the field is present (workflow_conductor.py:7190-7212). Note: `wrong = {… if name in source_refs …}`, so the comparison applies only to present keys.
  - vps `_validate_ir_source_refs_tests` (vps:11163) refuses a ref that is missing or unresolvable.
  - So the CONTENT is the operator's spec. The leaf's choice is limited to the ref, and the two checks above pin the ref.
- **S3: the three routes that reach the compile-stage gates** (`validate_compile_ir_dir` / `validate_compile_stage`):
  - (a) the conductor's `compile.static` gate, through the CLI `--stage compile`;
  - (b) the workshop wrapper's `check_ir` operation, which the LEAF invokes (workflow_conductor.py:11352/11380 → workshop_wrapper.py:192), and whose output is the leaf's feedback;
  - (c) `orchestration_runtime._certified_ir_violations` (orchestration_runtime.py:1884/1941), which re-checks an already-certified IR before it is reused.
  - Gates (m)/(o)/(r)/(q) are called from `_validate_tests_and_predicates` (vps:11123-11135, outside this range).
- **S4: records the host writes.** The post-execute records are written by the conductor:
  - `trial_meta.json`, including `source_command_ref`, `source_source_id`, `source_binary_id`, `kernel_trace` and `environment.launch` (workflow_conductor.py:14226-14260);
  - `verdict.json` at execute, and `summary.json` / `aggregate_verdict.json` at post_judge (workflow_conductor.py:800-835, 15654);
  - `semantic_review.json`, whose `review_method` literal and `scope` are host-composed (workflow_conductor.py:7457-7530). Only `decision`/`findings`/`notes` come from the judge leaf.
  - The lint/syntax evidence (workflow_conductor.py:12216, 12472, 12776) and `command_log.jsonl` (`build_runtime._append_command_log`).
  - The leaf-authored sub-values inside these host records:
    - the `ok` of `run_program`/`run_quality_checks`/`run_linter`/`run_syntax_check`, which is the exit status of a leaf-built program or a leaf-written source;
    - the case ids and binary file names inside a logged `command`;
    - `verification_status` in `source_meta.json`, which the host writes from the generate.verify leaf's verdict (workflow_conductor.py:1762);
    - `decision` in `semantic_review.json`.
  - Several docstrings in this range still describe a leaf forger, e.g. vps:5262 "Leaf-writable artifact (it is in the generate/verify `allowed_output_paths`)", vps:4905-4912, and vps:6971-6976 "prevents a child from pointing trial_meta at…".
